# atla.design v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild atla.design in the clean Cosmos-like style with an AI bar (search + brief), a step-by-step AI brief, every page redesigned, and an AI-ready site, launched all at once from `feat/site-v2`.

**Architecture:**
- **What stays:** the same React + Vite client, the Express API (served on Vercel through `api/index.ts`), Sanity content and the prerender build.
- **New server modules:** `server/ask/`, `server/brief/`, `server/ai/` and `server/limits/`. They hold the logic behind two new endpoints, `POST /api/ask` and `POST /api/brief/*`.
- **New client code:** a site shell (header, footer, tokens) in `client/src/components/site/`. All pages are rebuilt on that shell.
- **Copy:** every visible text lives in one file, `client/src/content/siteCopy.ts`, so JP reviews it in one place.

**Tech Stack:**
- Client: React 18, wouter, react-query, framer-motion (already installed).
- Server and content: Express, Sanity, Vercel.
- New dependencies: `@anthropic-ai/sdk` and `vitest` (dev only).
- Services: Resend over its HTTP API (no SDK), and Upstash Redis REST (plain fetch, no SDK).

**Spec:** `docs/superpowers/specs/2026-11-04-atla-site-from-scratch-design.md` (approved by JP 2026-11-04). Read it before any task.

## Review Focus

1. **AI or Attio down mid-brief.** The visitor still finishes, sees the confirmation and the Calendly button, and JP gets the email. If the email fails as well, the server logs the full brief at `error` level. (Task 6 test `submit survives Attio and AI failure`.)
2. **Spend cap or rate limit hit.** `/api/ask` falls back to keyword search with no AI and never shows an error. `/api/brief/next` falls back to the fixed question set. (Tasks 4 and 6 tests `cap reached uses fallback`.)
3. **Gibberish, empty, 2,000-character or script-tag input in the bar.** Input is trimmed and capped at 300 characters. The server returns `closest` projects or an empty-state that offers the brief, and nothing is rendered as HTML. (Task 4 test `ask handles junk input`.)
4. **Search with zero tag matches** (e.g. "hospital"). The server returns the 6 nearest projects by industry and service overlap, with `closest: true`, and the UI labels them "Closest work". (Task 4 test `no exact match returns closest`.)
5. **Leaving the brief and coming back.** Answers persist in `sessionStorage` (wrapped in try/catch), so a reload resumes at the same step. Submitting twice doesn't create two Attio notes. (Task 7 test `resume after reload`; Task 6 test `idempotent submit`.)

**Interfaces:**
- Produces:
  - `incrWithExpiry(key: string, ttlSeconds: number): Promise<number>`. It uses Upstash REST (`/pipeline` with `INCR` + `EXPIRE NX`) and falls back to an in-memory Map with a single `console.error("[limits] Upstash not configured, using per-instance memory")` per process.
  - `rateLimit(ip: string, bucket: "ask" | "brief"): Promise<boolean>`. The limits are ask 30 per 10 min and brief 20 per 10 min.
  - `aiBudgetAvailable(): Promise<boolean>` and `recordAiCall(): Promise<void>`. The key is `ai:YYYY-MM` and the cap is `AI_MONTHLY_CALL_CAP`. At 80% of the cap it logs `console.error` once per month as the alert.
  - `callClaudeJson<T>(opts: { system: string; user: string; schema: object; toolName: string; maxTokens?: number }): Promise<T | null>`. It returns null on a missing key, timeout (8 s), error or exhausted budget, and calls `recordAiCall` on every real call.
  - `rankProjects(query: string, projects: ProjectLite[]): { projects: ProjectLite[]; closest: boolean }`, where `ProjectLite = { slug, title, industry, region, services: string[], tags: string[], year, coverImage }`:
    - Tokenize and lowercase, then score title (3), industry (3), services (2), tags (2) and region (1).
    - If the top score is 0, return the 6 projects that share the most industry or service tokens with a synonym map (`hotel→hospitality`, `restaurant/cafe/coffee→hospitality`, `food/drink/beverage/beauty→consumer`, `fintech/ai/software/saas→tech`, `real estate/residence/fashion/retail→lifestyle`), with `closest: true`. If nothing overlaps, return the 6 most recent with `closest: true`.
  - `POST /api/ask` takes `{ q: string }` (trimmed, max 300) and returns either:
    - `{ kind: "results", projects: ProjectLite[], closest: boolean }`, or
    - `{ kind: "brief", seed: string }`.
  - Intent works in two passes:
    1. A heuristic first: a query that starts with or contains "we're / we are / i'm building / i need / our company / my brand / launching / rebrand" → brief.
    2. Ambiguous queries longer than 6 words go to `callClaudeJson` with tool `route_query`, whose schema is `{ kind: "results"|"brief", searchTerms: string }`. When the result is `results`, rank with `searchTerms`.
  - When the rate limit is hit, the budget is exhausted or the AI returns null, use heuristic plus keyword only. The endpoint never returns 5xx for those cases.

  - It answers `ok: true` whenever validation passes, even if Attio or the email failed. Each failure is logged with `console.error` and the full brief JSON.
  - Idempotency: `incrWithExpiry("brief:" + submissionId, 86400) > 1` → skip delivery and return the same response.
  - The summary text comes from `formatBriefSummary(state): string` (English, deterministic, no AI). Free-text answers are kept as written.
